## Project Overview

**classroom-api** is a single-page web application that wraps the Google Classroom API, letting educators and administrators view classes, students, assignments, and submissions through a custom UI. It authenticates users via Google OAuth 2.0 and calls the Classroom API directly from the browser.

Deployment targets:
- **Firebase Hosting** (primary, via `firebase deploy`)
- **GitHub Pages** (alternative, via `npm run deploy:github`)

## Development Workflow

### Prerequisites

- Node.js (v16+) and npm
- Firebase CLI: `npm install -g firebase-tools` then `firebase login`
- A Google Cloud project with Classroom API enabled and OAuth 2.0 credentials

### Environment Variables

Copy `.env.example` to `.env` and fill in values:

```
GOOGLE_CLIENT_ID=your-oauth-client-id
GOOGLE_API_KEY=your-api-key
```

These are injected at build time by `dotenv-webpack` and `webpack.DefinePlugin`. They are never committed — they live in `.env` locally or in GitHub Secrets in CI.

### Common Commands

```bash
# Local development (webpack-dev-server, hot reload, port 9000)
npm run dev

# Build for production
npm run build          # Firebase deploy target
npm run build:github   # GitHub Pages target (same webpack command)

# Deploy
npm run deploy         # Build + firebase deploy --only hosting
npm run deploy:github  # Build + git subtree push to gh-pages

# Firebase emulator (hosting + functions together)
npm start              # firebase emulators:start

# Standalone local server (serves /public on port 9000)
npm run server

# Functions-specific
cd functions
npm run lint           # ESLint
npm run serve          # firebase emulators:start --only functions
npm run deploy         # firebase deploy --only functions
npm run logs           # Stream function logs
```

## Architecture & Key Patterns

### Frontend (`src/index.js`)

The entire frontend is a single JS module (~466 lines). Key sections:

1. **OAuth initialization** — `google.accounts.oauth2.initTokenClient()` with classroom scopes
2. **API initialization** — `gapi.load('client')` → `gapi.client.init()` → `gapi.client.load('classroom', 'v1')`
3. **Course listing** — `gapi.client.classroom.courses.list()` with `pageSize: 100`
4. **UI rendering** — Pure DOM manipulation (`document.createElement`, `innerHTML`), no framework

**State variables** (module-level globals):
- `classesData[]` — Cached course objects from the API
- `currentClassId` — Selected course ID
- `currentClassFilter` — `"ACTIVE"` | `"ARCHIVED"`
- `currentAccessToken` — Live OAuth token string
- `isAuthenticated` — Boolean

**Partial implementations** (stubs that need finishing):
- `fetchStudents(courseId)`
- `fetchAssignments(courseId)`
- `prepareSubmissions(courseId)`
- `viewSelectedSubmissions()`
- `showClassDetails(courseId)`

### Firebase Cloud Function (`functions/index.js`)

Single HTTPS function `getApiCredentials` that returns `GOOGLE_CLIENT_ID` and `GOOGLE_API_KEY` from Firebase environment config. CORS is enabled for browser calls.

### CI/CD (`.github/workflows/deploy.yml`)

Trigger: push to `main` or manual `workflow_dispatch`

Steps:
1. Checkout → Setup Node 16 → `npm ci`
2. Generate `./src/config.js` dynamically from GitHub Secrets (`GOOGLE_CLIENT_ID`, `GOOGLE_API_KEY`)
3. `npm run build:github` (webpack production)
4. Deploy `/public` folder to `gh-pages` branch

## Coding Conventions

### Naming
- `camelCase` for all variables and functions
- `UPPER_SNAKE_CASE` for constants (e.g., `SCOPES`, `API_CREDENTIALS`)
- `is*` prefix for booleans (`isAuthenticated`)
- `current*` prefix for active-selection state (`currentClassId`, `currentAccessToken`)
- DOM element variables named descriptively without a suffix (e.g., `statusMessage`, `loadingIndicator`)

### Async Style
- Promise chains (`.then().catch().finally()`) — not `async/await`
- Timeout-based initialization guard with `setTimeout` + `reject`

### DOM Manipulation
- Vanilla JS only — no framework
- `document.createElement()` + property assignment for new elements
- Event listeners attached directly to created elements, not delegated

### CSS
- Material Design color palette (primary: `#4285f4`)
- Flexbox layouts
- Inline styles in HTML for above-the-fold critical styles; class-based elsewhere
- Class names follow BEM-like conventions: `.class-item`, `.class-name`, `.class-options`

### Error Handling
- `try/catch` with `console.error()` logging
- User-visible errors set on a `statusMessage` DOM element

## Security Notes

- **Never hardcode credentials** — use `.env` locally or GitHub Secrets in CI
- OAuth 2.0 token-only flow (no authorization code flow); tokens are not persisted
- `google.accounts.oauth2.revoke()` is called on sign-out to invalidate the token
- The Firebase Cloud Function is the secure proxy for credential delivery — it should remain server-side only

## What Does Not Exist (Yet)

- **No automated tests** — ESLint is configured for a Mocha test environment, but no test files exist
- **No TypeScript** — plain JS only
- **No state management library** — module-level globals are used
- **No routing library** — single view with show/hide logic

When adding features, stay consistent with the existing vanilla-JS, promise-chain style unless the scope warrants a larger refactor.
